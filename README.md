# Маргиналии

Веб-инструмент для вычитки Markdown-документов — научной статьи, главы книги, черновика, текста, подготовленного ИИ-агентом. Исходный документ показывается справа с номерами физических строк, а замечания собираются слева и экспортируются как один читаемый Markdown-файл. Текст остаётся в браузере читателя и никуда не отправляется.

Опубликованная версия: <https://marginalia-review.web.app>.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```sh
pnpm install
pnpm run dev
```

Откройте адрес, который напечатает Vite. Документы читаются через браузерный выбор файла и не загружаются на сервер.

Текст статьи не обязательно превращать в файл: кнопка «Вставить» открывает его прямо из буфера обмена. Chrome спрашивает разрешение один раз, Firefox и Safari показывают собственное меню «Вставить» — подавить его страница не может. Если браузер читать буфер не дал, приложение открывает окно, куда текст вставляют руками. Имя вставленной статьи берётся из поля `title` вводной части, иначе из первого заголовка, иначе остаётся общим; переименовать статью можно в любой момент — рецензия привязана к документу, а не к его имени.

## Хранение работы

Открытый документ и его рецензия попадают в браузерное хранилище (IndexedDB, база `marginalia`) и переживают закрытие вкладки, браузера и перезагрузку устройства. Замечания сохраняются сами, без команды: отметка «Сохранено» в шапке появляется после того, как запись действительно завершилась.

Приложение просит у браузера устойчивый режим хранения в момент, когда появляется первое замечание. Без него Safari удаляет данные источника после семи суток без взаимодействия, а прочие браузеры вытесняют их при нехватке места на диске. Если хранилище недоступно — приватное окно, запрет в настройках, — приложение продолжает работать, но только в памяти вкладки.

Пока устойчивого режима нет, приложение показывает полосу о том, где живёт рецензия. Она исчезает сама, как только приложение установлено, — в том числе если после установки открыть его обычной вкладкой. Полосу можно и просто закрыть: предупреждение сказано один раз, и повторять его при каждом открытии незачем.

Браузерное хранилище не заменяет резервную копию: очистка данных сайта, другой браузер или другое устройство означают пустое приложение. Готовую рецензию стоит выгружать кнопкой.

Файл узнаётся по SHA-256 его содержимого. Тот же файл, открытый повторно, возвращает прежнюю рецензию, а не заводит копию. Новая версия статьи добавляется отдельным действием и соседствует со старой; замечания между версиями не переносятся. Выгруженная рецензия открывается обратно: машинные данные лежат в HTML-комментарии, невидимом в просмотрщиках Markdown. Если рецензия написана к другой версии статьи, она всё равно открывается, но с предупреждением о возможном смещении привязки.

## Установка на устройство

Собранное приложение — устанавливаемое (PWA): открывается без сети и ставится на рабочий стол. Новая версия скачивается в фоне и вступает в силу при следующем открытии — код не подменяется под руками у человека, который правит рецензию; о состоявшемся обновлении приложение сообщает само.

## Размеры экрана

Раскладка рассчитана на настольный экран и планшет, нижняя граница — 720 px. До 1180 px панели сужаются, а счётчик замечаний и подпись сортировки уходят. До 1040 px скрывается оглавление: оно вспомогательное, а документу и рецензии нужна ширина. До 860 px колонки перестают помещаться рядом, и рецензия встаёт над документом; ручки изменения ширины в этом режиме скрыты. Горизонтальной прокрутки не возникает ни на одной из этих ширин — это проверяется браузерным сценарием.

## Публикация

```sh
pnpm run deploy
```

Команда собирает приложение и выкладывает `dist` на Firebase Hosting — отдельный сайт `marginalia-review` внутри проекта `my-nikita-tools`. Firebase раздаёт его по двум адресам; браузерное хранилище привязано к адресу, поэтому `marginalia-review.firebaseapp.com` перенаправляет на канонический `marginalia-review.web.app` до того, как приложение обратится к хранилищу. Штатного механизма перенаправления между двумя адресами по умолчанию у Firebase нет, поэтому оно сделано в самой странице.

## Проверка

```sh
pnpm run test:setup
pnpm test
```

Первая команда устанавливает Chromium для Playwright; её достаточно повторять после обновления версии браузера. Вторая запускает модульные проверки, производственную сборку и браузерные сценарии.

Стили сверяются с макетом в Claude Design отдельно, по собранному CSS: исходный и скомпилированный файлы различаются порядком свойств и потому напрямую несопоставимы. Различия, принятые осознанно, перечислены в `design-sync-accepted.txt` — сверка со списком должна возвращать ноль.

## Правила рецензии

- Замечания с привязкой автоматически упорядочиваются по строке, положению начала и конца выделения, затем по времени создания.
- Замечание с привязкой можно оставить без слов: тип и процитированные строки уже говорят, что не так. Общая запись состоит из одного текста, поэтому пустой она не добавляется.
- Многострочное выделение экспортируется как `### Строки N–M · Тип`.
- Общая запись не получает фиктивную строку. Она сохраняет выбранное место между замечаниями, даже если привязанные замечания позже добавлены или удалены.
- «Скопировать» и «Скачать» формируют один и тот же текст. «Скачать» предлагает выбрать место сохранения через File System Access API; там, где API недоступен (например, в Firefox), файл уходит обычной загрузкой браузера.
- Загруженный Markdown не исполняет HTML или JavaScript и не загружает встроенные изображения.
